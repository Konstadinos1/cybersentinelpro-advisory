Zero-trust guardrails for MCP and agentic AI

Assume the prompt injection succeeds. Then make it not matter.

aegis-mcp puts deterministic checks between an AI agent and everything it can touch: tools, shells, databases, vector stores and your users' screens. No check calls a model, so no check can be talked out of its answer.

    Design rules

    Default deny
    Unknown tools are withheld, unknown roles get nothing, and anything that cannot be parsed is rejected.
    Authorise the human, not the agent
    Every decision uses the verified user's roles and tenant. The agent's own credentials are never consulted.
    Approvals cover one exact action
    A human approval is tied to one tool call with one set of arguments, and works once.
    Model output is untrusted input
    It is parsed and checked against an allowlist before it reaches a shell, a database or a browser.
    Every attack is a regression test
    The cases in the lab run on every pull request. A missed attack or a blocked normal request fails the build.

    What it is not

    This is a reference implementation, and it says so. The poisoning scanner is pattern-based, so new phrasing can get past it; pinning is the control that does not depend on recognising the attack. Runtime state is held in memory. It has not been independently audited. The full list is in the README, and the threat model states the residual risk for each control.
